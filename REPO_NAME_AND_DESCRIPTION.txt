1. PREFERRED REPOSITORY NAME
--------------------------------------------------------------------------------
unlimited-ocr-everywhere

Why this name:
  - Reads naturally in a URL: github.com/you/unlimited-ocr-everywhere
  - Contains the exact model family people search for: "unlimited ocr"
  - The "everywhere" suffix signals the repo's differentiator: every hardware
    tier, not just the upstream A800 example.
  - Lowercase and hyphenated, so GitHub, Colab and Markdown links behave.

Alternative names (in order of preference):
  1. unlimited-ocr-anywhere
  2. unlimited-ocr-notebooks
  3. unlimited-ocr-for-everyone
  4. run-unlimited-ocr
  5. ocr-everywhere

Avoid:
  - baidu-unlimited-ocr (implies official affiliation; this is unofficial)
  - unlimited-ocr-colab (undersells the local/CPU/Apple/SGLang tiers)
  - best-ocr (spammy, not descriptive)

Title: Unlimited OCR Everywhere v1.0.0

Body:
  Six notebooks, one output format.

  - Colab T4: free, 16 GB, float16, one page per request
  - Colab L4/A100: BF16, larger chunks, long documents
  - Local NVIDIA GPU: Windows/Linux, auto device and chunk sizing
  - Local CPU: experimental float32 fallback
  - Apple Silicon: experimental MPS path
  - SGLang server: page-window scheduling for hundred-page books

  Also included: batch CLI (scripts/ocr_pdf.py), environment checker, vendored
  upstream post-processor, CI that validates every notebook, and issue
  templates for hardware reports.

  First run downloads ~7 GB of model weights. The practical GPU minimum is
  12 GB VRAM. CPU and Apple Silicon are labeled experimental on purpose.

  Full notes: README.md

  Baidu's Unlimited-OCR-2 is a 3B document parser with a 6.7 GB BF16 checkpoint.
  The upstream README targets an A800-80GB and SGLang, which is a high bar if
  you just want to OCR a PDF.

  I packaged it into six self-contained notebooks:
  - free Colab T4 (16 GB, float16, one page at a time)
  - Colab Pro L4/A100 (BF16, larger chunks)
  - local Windows/Linux NVIDIA (auto device/chunk)
  - CPU-only (experimental, float32)
  - Apple Silicon (experimental, MPS)
  - SGLang server (long documents, streaming)

  Each notebook renders PDFs/images, runs the model, converts the layout stream
  to Markdown, crops figures, and writes metadata. There is also a batch CLI and
  an environment checker that tells you which tier fits your machine.

  Honest limits: 12 GB VRAM is the practical GPU minimum, T4 is slow for long
  books, and CPU/Apple are experimental. The repo says so up front.

  Feedback on hardware combinations is very welcome.

13. NAMING / BRANDING NOTES
--------------------------------------------------------------------------------
- Keep "Unlimited OCR" capitalized in prose; keep "unlimited-ocr-everywhere"
  lowercase in the URL.
- Always include the "unofficial community project" line near the top. It is
  both honest and legally safer.
- Do not use the Baidu logo as the repo logo. The banner uses text only.
- The model name is "Unlimited-OCR-2" (with the hyphen and the 2). The upstream
  GitHub repo is "Unlimited-OCR".
- For citations, use the two BibTeX entries in README.md / CITATION.cff.
- If you rename the repo later, GitHub redirects the old URL, but Colab badges
  cached in other people's notebooks will keep working through the redirect.
